# 어떤 에이전트를 사용할까?

- 코딩 에이전트를 직접 만들지 않고 `완성된 제품`을 쓰는 선택지
- 대표적으로 `Claude Code`, `Codex`, `Gemini CLI` 세 가지
- 세 도구 모두 터미널에서 코드베이스를 읽고 파일을 수정하고 명령을 실행함
  - 할 수 있는 일의 목록은 비슷하므로, `무엇이 다른지`를 보고 골라야 함

> ⚠️ 이 영역은 변화가 매우 빠릅니다. 모델, 가격, 한도는 수시로 바뀌므로 아래 내용은 방향성으로만 참고하고 실제 수치는 공식 문서에서 확인하는 것을 권장합니다.

## 한눈에 비교

| | Claude Code | Codex | Gemini CLI |
| --- | --- | --- | --- |
| 만든 곳 | Anthropic | OpenAI | Google |

| 무료 사용 | 구독 또는 API 키 필요 | ChatGPT 구독 기반 | `분당 60회 / 일 1,000회` |
| 실행 환경 | 터미널, VS Code, JetBrains, 데스크톱 앱, 웹, 모바일 | 터미널, IDE 확장, ChatGPT 앱(데스크톱·모바일·웹), 클라우드 | 터미널 중심 |
| 컨텍스트 파일 | `CLAUDE.md` (+ `AGENTS.md`도 읽음) | `AGENTS.md` | `GEMINI.md` |

| 내장 웹 검색 | 지원 | 지원 | `Google Search 그라운딩` |

## AGENTS.md — 공통 표준

- 세 도구를 비교할 때 먼저 알아둘 것은 `프로젝트 컨텍스트 파일이 사실상 표준화되었다`는 점
- `AGENTS.md`는 코딩 에이전트를 위한 개방형 표준
  - "사람을 위한 README가 있다면, 에이전트를 위한 README"
  - 빌드 방법, 테스트 실행법, 코드 컨벤션 등을 적어둠
  - 6만 개 이상의 오픈소스 프로젝트, 30개 이상의 에이전트가 지원
- 도구를 바꿔도 `AGENTS.md는 그대로 쓸 수 있음`
  - Claude Code는 `CLAUDE.md`가 없으면 `AGENTS.md`를 읽음
  - 도구 종속성을 줄이려면 공통 내용은 `AGENTS.md`에, 도구별 특수 설정만 각자의 파일에 두는 방식이 깔끔함

## Claude Code

### 성격

- `확장 메커니즘과 실행 환경의 폭`이 가장 넓은 쪽
- 터미널에서 시작한 세션을 IDE, 데스크톱 앱, 웹, 모바일로 옮겨가며 이어갈 수 있음

### 확장 수단

| 수단 | 용도 |
| --- | --- |
| `CLAUDE.md` | 프로젝트 상시 컨텍스트 (자동 메모리도 누적) |
| 슬래시 커맨드 | 자주 쓰는 프롬프트를 명령으로 등록 |
| 스킬 | 반복 워크플로우를 패키징해 팀과 공유 |
| 서브에이전트 | 작업을 병렬로 쪼개 위임 |
| 훅(Hooks) | 파일 수정 후 포맷, 커밋 전 린트 등 자동 실행 |
| MCP | 외부 데이터·도구 연결 |
| Agent SDK | Claude Code의 하네스를 라이브러리로 사용 |

### 강점

- `팀 단위로 워크플로우를 표준화`하기 좋음 — 스킬과 슬래시 커맨드를 저장소에 커밋해 공유
- `훅으로 결정론적 자동화`를 끼워넣을 수 있음. 모델의 판단에 맡기지 않고 강제되는 단계를 만들 수 있다는 점이 다른 도구와의 차별점
- 파이프라인 친화적 — `tail -200 app.log | claude -p "..."` 형태로 Unix 도구와 조합
- CI 연동(GitHub Actions, GitLab CI), 예약 실행, Slack 연동 등 자동화 표면이 넓음

### 약점

- `비공개 소스`. 내부 동작을 들여다보거나 포크해서 고칠 수 없음
- `무료 티어가 없음`. 구독이나 API 키가 필요해 학습용으로 가볍게 시작하기에는 부담
- 기능이 많아 `학습 곡선`이 있음. 스킬·훅·서브에이전트를 다 쓰려면 익힐 것이 적지 않음

<br>

## Codex

### 성격

- `ChatGPT 생태계에 통합`된 형태
- CLI뿐 아니라 ChatGPT 데스크톱·모바일·웹 앱에서 바로 작업을 지시할 수 있음
- 클라우드 환경에서 작업을 위임하고 결과만 받아보는 흐름을 지원

### 강점

- `이미 ChatGPT를 쓰고 있다면 추가 비용과 학습이 가장 적음`
- `작업 위임`에 초점이 맞춰져 있음 — 모바일에서 과업을 던지고 결과를 받는 사용 패턴이 자연스러움
- `CLI가 Apache 2.0 오픈소스`로 공개되어 있어 동작 확인과 수정이 가능
- 코드 리뷰와 자동 검토 기능이 제품에 내장됨

### 약점

- 개발자 문서가 ChatGPT 학습 센터로 흡수되어 `레퍼런스 접근성이 떨어짐`
  - 샌드박스 모드나 승인 정책 같은 세부 동작을 문서에서 찾기 번거로움
- 터미널 중심 워크플로우의 확장 수단이 Claude Code만큼 세분화되어 있지 않음
- ChatGPT 구독 체계에 묶여 있어 `사용량 정책이 제품 전반과 연동됨`

<br>

## Gemini CLI

### 성격

- `완전 오픈소스(Apache 2.0)`에 넉넉한 무료 한도를 제공하는 터미널 에이전트
- Google 계정만 연결하면 `분당 60회, 일 1,000회`까지 무료

### 강점

- `진입 장벽이 가장 낮음` — 비용 걱정 없이 학습하고 실험하기에 최적
- `Google Search 그라운딩이 내장`되어 최신 정보가 필요한 작업에 유리
  - 라이브러리 최신 버전, 최근 바뀐 API 같은 주제에서 체감됨
- 오픈소스이므로 `동작을 읽고 고칠 수 있음`. 사내 환경에 맞게 포크하는 선택지가 열려 있음
- 대용량 컨텍스트(1M 토큰)로 큰 코드베이스를 한 번에 밀어넣는 방식이 가능

### 약점

- `실행 환경이 터미널 중심`. IDE·데스크톱·모바일로 이어지는 흐름은 약함
- 스킬·훅에 해당하는 `결정론적 자동화 수단`이 상대적으로 얕음
- 생태계와 서드파티 통합의 축적이 다른 둘보다 적음

<br>

## 작업별 선택 가이드

| 하려는 일 | 적합 | 이유 |
| --- | --- | --- |
| 처음 배우기, 비용 없이 실험 | `Gemini CLI` | 무료 한도가 넉넉하고 설치만으로 시작 |
| 대규모 코드베이스 탐색·이해 | `Gemini CLI` / `Claude Code` | 큰 컨텍스트, 또는 서브에이전트로 병렬 탐색 |
| 멀티파일 기능 구현 | `Claude Code` / `Codex` | 계획 수립과 다단계 편집의 완성도 |
| 팀 워크플로우 표준화 | `Claude Code` | 스킬·슬래시 커맨드·훅을 저장소에 커밋해 공유 |
| CI에서 자동 리뷰·트리아지 | `Claude Code` / `Codex` | CI 연동과 코드 리뷰 기능이 제품에 포함 |
| 커밋 전 린트 등 강제 단계 | `Claude Code` | 훅으로 모델 판단과 무관하게 강제 가능 |
| 모바일에서 작업 위임 | `Codex` / `Claude Code` | ChatGPT 앱, 또는 웹·모바일 세션 |
| 최신 정보가 필요한 작업 | `Gemini CLI` | Search 그라운딩 내장 |
| 사내 환경에 맞게 개조 | `Gemini CLI` / `Codex` | 오픈소스라 포크 가능 |
| 이미 쓰는 구독 활용 | 구독 중인 쪽 | 추가 비용 없음이 가장 큰 변수 |

## 고를 때 실제로 중요한 것

- `모델 성능 차이는 생각보다 빨리 수렴하고 빨리 뒤바뀜`
  - 벤치마크 몇 점 차이로 고르면 다음 달에 판단이 뒤집힘
  - 오래 유지되는 차이는 `생태계`, `확장 방식`, `실행 환경`, `라이선스`
- `이미 쓰는 구독`이 가장 현실적인 기준인 경우가 많음
  - 세 도구의 기본 작업 수행 능력은 비슷한 수준에 도달해 있음
- `도구 종속을 줄이는 쪽`으로 설정을 설계해 두면 전환 비용이 낮아짐
  - 프로젝트 컨텍스트는 `AGENTS.md`에 모으기
  - 도구별 설정 파일에는 그 도구만의 기능만 남기기
- 결국 `직접 써보는 것`이 가장 빠름
  - 세 도구 모두 설치가 간단하고, Gemini CLI는 무료로 바로 시작 가능
