# CLAUDE.md로 프로젝트 컨텍스트 주기

- 모든 세션은 `빈 컨텍스트 윈도우로 시작`함
  - 어제 설명한 것을 오늘 다시 설명해야 함
- `CLAUDE.md`는 그 반복을 없애는 파일
  - 세션이 시작될 때마다 자동으로 읽힘
  - 빌드 명령, 코드 규칙, 프로젝트 구조, "항상 X 해라" 같은 규칙을 적어둠

> ⚠️ **CLAUDE.md는 컨텍스트이지 강제 설정이 아니다.**
> 시스템 프롬프트가 아니라 `사용자 메시지로 전달`되므로, 모델이 읽고 따르려 하지만 엄격한 준수가 보장되지 않는다. 반드시 매번 실행돼야 하는 것은 지시가 아니라 `훅(Hook)`으로 써야 한다.

<br>

## 언제 추가하나

다음 네 가지가 `추가 신호`다.

- Claude가 `같은 실수를 두 번째로` 함
- 코드 리뷰에서 Claude가 알았어야 할 것이 지적됨
- 지난 세션에 입력했던 `같은 교정을 또` 입력하고 있음
- 새 팀원이라면 같은 설명을 필요로 할 내용

즉 `어차피 다시 설명하게 될 것을 미리 적어두는 곳`이다.

<br>

## 어디에 두나

위치마다 범위가 다르고, 아래 순서대로(넓은 범위 → 좁은 범위) 로드된다.

| 범위 | 위치 | 용도 | 공유 대상 |
| --- | --- | --- | --- |
| 조직 정책 | OS별 시스템 경로 | 회사 표준, 보안 정책 | 조직 전체 |
| 사용자 | `~/.claude/CLAUDE.md` | 모든 프로젝트에 적용되는 개인 취향 | 나만 (전 프로젝트) |
| 프로젝트 | `./CLAUDE.md` 또는 `./.claude/CLAUDE.md` | 팀 공유 규칙 | 팀 (버전 관리로) |
| 로컬 | `./CLAUDE.local.md` | 개인 프로젝트 설정 | 나만 (현재 프로젝트) |

- `CLAUDE.local.md`는 `.gitignore`에 넣어야 함 — 내 샌드박스 URL, 선호하는 테스트 데이터 같은 것
- 프로젝트 파일은 버전 관리로 공유되므로, `개인 취향이 아니라 프로젝트 표준`만 담아야 함

### 로드 방식

- 작업 디렉토리와 `그 위의 모든 디렉토리`에서 파일을 찾아 로드함
  - `foo/bar/`에서 실행하면 `foo/bar/CLAUDE.md`와 `foo/CLAUDE.md`를 모두 읽음
- 발견된 파일들은 `덮어쓰지 않고 이어붙여짐`
  - 파일시스템 루트 → 작업 디렉토리 순서
  - 즉 `실행 위치에 가까운 지시가 나중에 읽힘`
  - 같은 디렉토리에서는 `CLAUDE.local.md`가 `CLAUDE.md` 뒤에 붙음
- `하위 디렉토리`의 CLAUDE.md는 시작 시점이 아니라 `온디맨드`로 로드됨
  - Claude가 그 디렉토리의 파일을 읽거나 수정할 때 로드
  - 그래서 `/context`의 목록에는 보이지 않음
- 로드 여부 확인: 세션에서 `/context` 실행 → **Memory files** 항목 확인

<br>

## 시작하기

```
/init
```

- 코드베이스를 분석해 빌드 명령, 테스트 방법, 발견한 규칙으로 초안을 만들어줌
- 이미 파일이 있으면 덮어쓰지 않고 `개선안을 제안`함
- 초안에서 시작해, `Claude가 스스로 알아낼 수 없는 것`을 채워 넣는 방식으로 다듬음

<br>

## 효과적으로 쓰는 법

### 검증 가능할 만큼 구체적으로

| 모호함 | 구체적 |
| --- | --- |
| 코드를 깔끔하게 포맷해라 | `2칸 들여쓰기를 쓴다` |
| 변경사항을 테스트해라 | `커밋 전에 npm test를 실행한다` |
| 파일을 잘 정리해라 | `API 핸들러는 src/api/handlers/ 에 둔다` |

### 크기 — 200줄을 목표로

- `길수록 컨텍스트를 더 먹고 준수율이 떨어짐`
- 각 줄마다 이렇게 물어볼 것

> 이 줄을 지우면 Claude가 실수를 하게 될까?

- 아니라면 지운다
- 권장 길이를 넘으면 시작 시점과 `/status`에서 경고가 표시됨

### 넣을 것과 빼야 할 것

| ✅ 넣기 | ❌ 빼기 |
| --- | --- |
| Claude가 추측할 수 없는 셸 명령 | 코드를 읽으면 알 수 있는 것 |
| 기본값과 다른 코드 스타일 규칙 | 언어의 표준 관례 |
| 테스트 실행 방법과 선호 러너 | 상세한 API 문서 (링크로 대체) |
| 저장소 예절 (브랜치 명명, PR 규칙) | 자주 바뀌는 정보 |
| 프로젝트 고유의 아키텍처 결정 | 긴 설명이나 튜토리얼 |
| 자명하지 않은 함정과 동작 | 파일별 코드베이스 설명 |

### 지시가 무시된다면 파일이 긴 것이다

- 규칙이 있는데도 Claude가 계속 다르게 행동하면, `파일이 너무 길어서 그 규칙이 묻힌 것`
- 한 줄에만 `IMPORTANT`를 붙이는 건 효과가 있지만, `여러 줄에 붙이면 아무것도 두드러지지 않음`
- CLAUDE.md에 있는 내용을 Claude가 되묻는다면 `표현이 모호한 것`

### 코드처럼 다룬다

- 문제가 생기면 리뷰하고, 정기적으로 덜어내고, 행동이 실제로 바뀌는지 관찰해 검증
- git에 커밋해서 팀이 함께 기여하게 할 것 — `시간이 지나면서 가치가 누적되는` 파일
- `/doctor` 점검은 커밋된 CLAUDE.md에서 덜어낼 내용을 제안함
  - 코드베이스에서 유도 가능한 것(디렉토리 구조, 의존성 목록, 아키텍처 개요)은 자르고
  - 함정, 근거, 기본값과 다른 규칙은 남김

<br>

## 파일을 쪼개는 방법

### @path 임포트

```text
프로젝트 개요는 @README, 사용 가능한 명령은 @package.json 참고.

# 추가 지시
- git 워크플로우 @docs/git-instructions.md
```

- 상대 경로는 `임포트를 작성한 파일 기준`으로 해석됨
- 재귀 임포트 가능 (최대 4단계)
- 경로에 공백이 있으면 백슬래시로 이스케이프: `@Design\ Docs/api.md`
- 백틱으로 감싸면 임포트되지 않음 — 문서에서 경로를 `언급`만 하고 싶을 때

> ⚠️ **임포트는 조직화에 도움이 되지만 컨텍스트 비용을 줄이지 않는다.**
> 임포트된 파일도 시작 시점에 함께 로드되기 때문이다. 길이를 줄이려면 아래 `경로 범위 규칙`을 써야 한다.

### .claude/rules/ — 경로 범위 규칙

```
your-project/
├── .claude/
│   ├── CLAUDE.md
│   └── rules/
│       ├── code-style.md
│       ├── testing.md
│       └── security.md
```

- `paths` 프론트매터로 특정 파일에만 적용되게 할 수 있음

```markdown
---
paths:
  - "src/api/**/*.ts"
---

API 핸들러는 반드시 ...
```

- `일치하는 파일을 다룰 때만 로드`되므로 평소 컨텍스트를 아낌
- `paths`가 없는 규칙은 시작 시점에 로드됨 (`.claude/CLAUDE.md`와 같은 우선순위)

### 스킬과의 구분

| | CLAUDE.md / rules | 스킬 |
| --- | --- | --- |
| 로드 시점 | 매 세션 (또는 경로 일치 시) | 호출하거나 관련 있다고 판단될 때 |
| 담는 것 | 항상 지켜야 할 규칙 | 때때로 필요한 절차·지식 |
| 적합 | 코드 스타일, 빌드 명령 | 다단계 워크플로우, 특정 도메인 지식 |

- 여러 단계로 된 절차이거나, 코드베이스의 `일부에서만` 의미가 있다면 CLAUDE.md가 아니라 스킬이나 경로 범위 규칙으로 옮길 것

<br>

## auto memory와의 차이

Claude Code에는 두 개의 메모리 체계가 있고, 둘 다 매 세션 로드된다.

| | CLAUDE.md | auto memory |
| --- | --- | --- |
| 작성자 | `내가` 씀 | `Claude가` 씀 |
| 내용 | 지시와 규칙 | 배운 것과 패턴 |
| 범위 | 프로젝트·사용자·조직 | 저장소 단위 |
| 용도 | 코딩 표준, 워크플로우, 아키텍처 | 내 취향, 내가 준 교정, 코드에서 유도 못 하는 맥락 |

- auto memory는 `~/.claude/projects/<project>/memory/` 에 저장됨
  - `MEMORY.md`가 색인이고, 시작 시 `첫 200줄 또는 25KB`까지만 로드됨
  - 상세 내용은 별도 주제 파일에 두고 필요할 때 읽음
- "항상 pnpm을 써라" 같은 걸 기억하라고 하면 auto memory에 저장됨
  - CLAUDE.md에 넣고 싶으면 `"이걸 CLAUDE.md에 추가해줘"`라고 명시
- `/memory`로 둘 다 조회·편집 가능

<br>

## AGENTS.md와의 관계

다른 코딩 에이전트용으로 `AGENTS.md`를 이미 쓰고 있다면, Claude Code가 그것을 읽을 수 있다.

| 저장소 상태 | Claude가 읽는 것 |
| --- | --- |
| `AGENTS.md`만 있음 | `AGENTS.md` |
| `AGENTS.md`와 `CLAUDE.md`가 함께 있음 | `CLAUDE.md`만 |
| `CLAUDE.md`가 `AGENTS.md`를 임포트 | `CLAUDE.md` (임포트로 둘 다) |

- 기본 동작은 `CLAUDE.md가 있으면 그것만` 읽는 것
  - 주의: 개인용 `CLAUDE.local.md`를 추가하면 `AGENTS.md`를 읽지 않게 됨
- 둘 다 읽게 하려면 **Project instructions** 설정을 변경
- 도구 중립적으로 가려면 공통 내용을 `AGENTS.md`에 모으고 `CLAUDE.md`에서 임포트하는 방식이 깔끔함

<br>

## 문제 해결

### 지시를 따르지 않는다

1. `/context` 실행 → **Memory files**에 해당 파일이 있는지 확인. 없으면 Claude가 볼 수 없는 상태
2. 지시를 더 구체적으로 — "포맷을 예쁘게"보다 "2칸 들여쓰기"
3. `충돌하는 지시`가 없는지 확인. 두 파일이 다른 지침을 주면 모델이 임의로 하나를 고름
4. 파일이 긴지 확인 — 길면 규칙이 묻힘
5. 특정 시점에 반드시 실행돼야 하는 것이면 `훅`으로 옮길 것

### /compact 후에 지시가 사라진 것 같다

- `프로젝트 루트의 CLAUDE.md는 압축을 견딤` — 압축 후 디스크에서 다시 읽어 주입됨
- 사라졌다면 셋 중 하나
  - 대화 중에만 말한 지시였다 → CLAUDE.md에 적어야 유지됨
  - 하위 디렉토리의 CLAUDE.md인데 아직 다시 로드되지 않았다
  - 경로 범위 규칙인데 일치하는 파일을 아직 다루지 않았다

### 파일을 감사하고 싶다

```
/doctor prompt-audit
```

- 오래된 지시, 존재하지 않는 파일·명령 참조, 서로 모순되는 내용을 찾아줌
- 보고서와 수정 제안을 주고, `적용을 요청하기 전까지 파일은 바뀌지 않음`

<br>

## 체크리스트

```
□ /init으로 초안 생성
□ 200줄 이내 유지
□ 각 줄: "지우면 Claude가 실수할까?" — 아니면 삭제
□ 지시가 검증 가능할 만큼 구체적인지
□ 코드를 읽으면 알 수 있는 내용은 제거
□ 일부 경로에만 필요한 규칙은 .claude/rules/로 분리
□ 다단계 절차는 스킬로 분리
□ 개인 설정은 CLAUDE.local.md에 두고 .gitignore 확인
□ git에 커밋해 팀과 공유
□ /context로 실제 로드 확인
□ 반드시 매번 실행돼야 하는 것은 훅으로
```
